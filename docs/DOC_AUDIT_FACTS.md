# Documentation audit facts

This file records the repository evidence used to keep public-facing docs accurate. It describes this checkout, not the ownership or publication status of external services.

## Identity and scope

- Canonical checkout: `https://github.com/danny-dis/letty` (`git remote -v`). Maintained derivative of the project credited in the root `README.md`; the root `LICENSE` retains Mario Zechner's 2025 copyright and MIT terms.
- The root `package.json` defines 11 primary package workspaces in `packages/*` and `packages/session-backends/*`: `chord`, `letty-tui`, `letty-telemetry`, `letty-ai`, `letty-agent-core`, `letty-session-backend-sqlite-node`, `letty-protocol`, `letty-client`, `letty-server`, `letty-coding-agent`, and `letty-evals`. Five extension examples are additional workspaces. The generated install-lock package is not a primary workspace.
- CLI package: `packages/coding-agent/package.json` maps the `letty` binary to `dist/bundle/cli.js`. After a build, `node packages/coding-agent/dist/bundle/cli.js --help` works on this Windows host. `letty-test.sh` invokes the source CLI through `tsx`, but fails here when MSYS-style paths are not translated for native Node (`C:\\c\\...` tsconfig path). The CLI offers interactive, print, JSON, and RPC modes (`packages/coding-agent/src/cli/args.ts`).
- Model catalogs are generated by `packages/ai/scripts/generate-models.ts`. The Kimi Coding provider uses the `kimi-code-plan-cn` catalog ID and exposes `kimi-coding` in the generated provider map. Model availability can change with upstream catalogs.

## Local commands and boundaries

- Node >=22.19.0 (`package.json`, package manifests). Install without dependency lifecycle scripts: `npm install --ignore-scripts` for local development; CI uses `npm ci --ignore-scripts` (`.github/workflows/ci.yml`).
- `npm run build` refreshes live model data and builds packages; it needs network access. `npm run build:offline` consumes existing generated model data. `npm run check` runs formatting, dependency and rebrand checks, typechecking, and browser smoke. `./test.sh` isolates the test environment and strips credentials; it invokes `npm test` (which may still expose platform-specific failures). `letty-test.sh --no-env` intends to run the source CLI with common API credentials removed but is not portable to this host's disabled MSYS native-path translation; use the built CLI command above for the reader-facing quickstart.
- CI (`.github/workflows/ci.yml`) runs build, check, rebrand guard, and test on Ubuntu. The issue/PR gates in `.github/workflows/issue-gate.yml` and `pr-gate.yml` close new contributors' submissions unless approved; their bot text makes a daily-review claim that the workflow cannot itself guarantee.
- The CLI runs with the invoking user's permissions. Project trust controls whether project-local configuration and extensions are loaded, not a filesystem/process sandbox (`packages/coding-agent/docs/security.md`, `packages/coding-agent/docs/containerization.md`).
- `packages/coding-agent/src/utils/version-check.ts` requests `https://letty.dev/api/latest-version`; `packages/coding-agent/src/modes/interactive/interactive-mode.ts` can send an install/version ping to `https://letty.dev/api/report-install`. `--offline` or `LETTY_OFFLINE=1` disables these startup operations; `LETTY_SKIP_VERSION_CHECK=1` and `LETTY_TELEMETRY=0` control them separately. The repo does not establish that `danny-dis` owns those endpoints.
- GitHub private vulnerability reporting is disabled for `danny-dis/letty` (GitHub API `repos/danny-dis/letty/private-vulnerability-reporting` reported `enabled: false` during this audit). Do not direct reports to `security@letty.dev` without confirmed ownership.
- The repository's package names and code do not by themselves establish that the npm `@letty` namespace, `letty.dev` installer, or Discord invite are operated by this maintainer. The package manifests still contain upstream `github.com/letty/letty` repository metadata; metadata changes would require lockfile/shrinkwrap review and are outside a docs-only rewrite.

## Documentation decisions

- `README.md`: replace logo, badges, external distribution claims, and incomplete package list with identity, source-based quickstart, full package map, trust/network caveats, and verified local commands.
- `CONTRIBUTING.md`: retain the gate documented by workflows, remove unsupported review-time promises and external chat guidance, and give reproducible contribution steps.
- `SECURITY.md`: keep the local trust boundary but remove third-party email/infrastructure claims; explain a safe way to request a private reporting channel while private reporting is disabled.
- `packages/coding-agent/README.md`: preserve technical reference content; replace its external installer/ownership assumptions and inherited branding footer with a derivative notice and repo-local guidance.
- `packages/coding-agent/docs/index.md` and `quickstart.md`: guide readers through this repository's source build first; keep deep reference links without asserting external distribution ownership.
- Package API references (`packages/ai/README.md`, `packages/agent/README.md`) and internal design notes remain intact; rewrite them only when a concrete inaccuracy is verified.
